# 组子细工绘图助手 - 技术方案修订版 V2

> 基于《需求&技术选型文档》（V1）评审结论，经逐项确认后修订。
> V1 原文保留不覆盖，本文档为**实施依据**。
>
> 确认结论（4 项）：
> 1. 画布渲染层：**SVG + Vue 声明式**，替代 vue-konva/Konva；
> 2. 数据模型：**参数化线族（pattern）→ 求交派生线段（segment）**，替代自由手绘散线；
> 3. 排样算料：**1D 切割清单（cut list）**，不引入 rectangle-packer；
> 4. MVP 补入：撤销/重做、网格吸附 + 平行/角度约束、坐标单位 = mm（线宽=物理宽度）、core 配 Vitest。

## 0. 相对 V1 的变更摘要

| 类别 | V1 | V2 | 原因 |
|------|----|----|------|
| 渲染层 | vue-konva + Konva | **SVG（原生 `<svg>` + Vue v-for）** | 数据即坐标；声明式重绘；原生拾取/框选；矢量导出（激光切割/打印）；几千线段性能足够；无版本绑定层风险 |

| 数据模型 | 手绘线段数组 | **参数化线族 + 派生线段** | 组子图案本质是平行线族叠交；调间距=改参数全图重排；算料/AI 生成均顺畅 |
| 排样 | rectangle-packer（2D） | **自研 1D cut list（Phase 3）** | 组子算料是"木条按标准条长一维下料"，非 2D 板面排样 |
| Worker | Phase 1 即考虑 Comlink | **延后到 Phase 3 排样搜索时** | 线段级几何为微秒级计算，提前引入徒增复杂度 |
| 交互能力 | —（缺） | **撤销/重做、网格吸附 + 角度约束** | 精确绘图工具的前置能力 |
| 单位语义 | 坐标+strokeWidth(px) 混用 | **全画布逻辑单位 = mm；线宽=物理宽度×缩放** | 0.1mm 精度必须基于物理坐标系统 |
| 测试 | —（缺） | **Vitest（core 全量单测）** | core 纯函数化是测试友好架构 |
| AI（Phase 4） | LLM 直出数据 | **本地参数化纹样生成器 + LLM 仅 NL→参数** | 避免 LLM 幻觉坐标/精度灾难 |
| UI 库 | Naive UI / shadcn-vue 未定 | **Naive UI** | 组件全、开箱即用、中文生态；shadcn-vue 需 Tailwind+自维护，收益低 |

## 1. 项目概述与需求（修订版）

面向"组子细工"爱好者的 **2D 精确制图 + 算料工具**。核心价值：用户通过**定义平行线族**（角度、间距、条数、线宽）快速搭建组子图案，系统自动求交切分并实时给出每段木条精确尺寸，为裁切提供 cut list。

### 1.1 核心功能需求
1. **图案（线族）的增删改查**
   - 增：以"绘制一族平行线"为基本操作（拖拽/面板参数），支持叠加多个线族构成图案。
   - 删：选中线族或单段，Delete 或按钮删除。
   - 改：选中后在属性面板修改**线族参数**（angle / spacing / count / width / bounds），全图即时重排；单段可覆盖宽度。
   - 查：点选、框选，属性面板显示选中线族/线段参数与派生尺寸。
2. **自动计算各线段尺寸（派生数据）**
   - 每条派生线段实时显示长度（精确到 0.1mm）。
   - 支持显示相邻线族/线段之间距离（平行间距由参数直接给出，非平行可求交点辅助判断）。
3. **纯 2D 平面绘图**，无 3D。
4. **调整间距与宽度（参数化驱动）**
   - 间距：属性面板用「Nx 倍数下拉」（Nx = N × 全局间距单位）改线族 `spacing` 或单线「相邻线间距」→ 全族/该线按新间距重排、交点重算。这是 V2 相对"选中多条线做等距"的根本改进。
   - 全局间距单位：项目级设置，默认 **10mm**（算料抽屉「参数」区可改，随项目持久化/可撤销）；组子图案按同一基本单位布排，间距面板值 = 该单位整数倍（1x–8x，超出自动扩展；历史遗留的非整倍值以「自定义」项原样保留）。
   - 宽度：族级默认宽度 + 段级覆盖；宽度 = 木条物理宽度（mm），渲染宽度随缩放换算。
5. **编辑环境基础能力（MVP 新增）**：撤销/重做、网格吸附、平行/角度约束（步进式角度）。
6. **算料（Phase 3）**：汇总各长度木条 → 计入端部斜切余量与锯缝 → 按标准条长做 1D 下料 → 输出 cut list + 余料与利用率。
7. **AI 生成纹样（Phase 4，可选）**：自然语言 → 结构化参数 → 本地纹样生成器产出线族。

## 2. 技术选型（确认版，纯 JavaScript，无 TypeScript）

| AI（可选） | **本地纹样生成器（参数化）+ LLM 仅做 NL→参数解析**（JSON/function-calling） | 不建议让 LLM 直接生成坐标/纹样数据 |
| 桌面（可选） | **Tauri** | Phase 5，不变 |
| Web Worker | Phase 3 排样搜索再评估（届时 Comlink） | 不提前引入 |

## 3. 数据模型（核心修订）

### 3.1 画布坐标系
- 逻辑单位 = **mm**。`1 unit = 1mm`。渲染像素由视图层统一换算：`screen = world × zoom + pan`，SVG 用 `viewBox` 承载。
- 图案坐标可含负值（以画布原点或板材参考角为原点均可），`bounds` 界定绘制范围。

### 3.2 Pinia state（纯数据）
```javascript
// stores/project.js —— 仅持久化此 store
state: () => ({
  version: 2,
  patterns: [
    {
      id: 'p1',                 // 唯一 id
      kind: 'family',           // 目前唯一类型：平行线族；保留扩展位（环形等）
      ref:   { x: 0, y: 0 },    // 参考点（过该点的第 0 条线）
      angle: 60,                // 线方向（度；正角 CCW，画布 y 向下需约定）
      spacing: 8,               // 相邻线垂直间距（mm）—— 需求中的“间距”
      count: 5,                 // 该族线条数
      width: 3,                 // 木条物理宽度 mm（族级默认）
      bounds: { x: -100, y: -100, w: 200, h: 200 } // 绘制范围（mm）
    }
  ],
  material: {                   // 算料输入（Phase 3 使用）
    stockLength: 1200,          // 标准条长 mm（可多规格）
    kerf: 1.5,                  // 锯缝 mm
    endTrim: 'miter45'          // 端部处理（决定切角余量算法）
  }
})

// stores/ui.js —— 不持久化
state: () => ({
  tool: 'select',               // select | pattern | pan
  zoom: 2, pan: { x: 0, y: 0 },
  selected: { patterns: [], segments: [] },  // 选中项（只存 id）
  snap: { grid: 1, angleStep: 15 },          // 网格 1mm、角度步进 15°
  show: { dimensions: true, grid: true }
})
```

### 3.3 派生数据（不存 store，不持久化）
- **派生线段**：`deriveSegments(patterns) → segments[]`（纯函数）
```javascript
{ id: 's_p1_2_3', x1, y1, x2, y2,   // 两个相邻交点切出的段（mm）
  width, patternId, lineIndex,      // 该段所属线族与线序
  length }                          // Math.hypot(...)（派生时算好或读取时算）
```
- 存放策略：`store.getters.segments` 或 composable 内**带版本校验的缓存**（patterns 数组引用/版本号未变则复用，避免每帧全量重算）。
- 派生段是"只看不改"的只读结果；任何编辑都落在 patterns 参数上。

## 4. 派生算法要点（core/patterns/derive.js）

对每个线族 `{ref, angle, spacing, count, bounds}`：
1. 生成无限直线集合：第 i 条线 = 过 `ref + i·spacing·n`、方向 `angle` 的直线（n 为法向）。
2. 收集切点：该线与**所有其他线族的每条线**求交，以及与 `bounds` 四边求交。
3. 切段：将该线上切点按参数 t 排序，取落在 bounds 内的相邻切点对 → 生成 segment。
4. 悬空端处理：最外侧线段若仅一侧有切点，按 bounds 边界裁断（避免无限长）。
5. 同族相邻线间距即 `spacing`（由参数直接给出，用于"显示间距"）；平行判定用角度差归一化。

> 实现要点：全部为 2D 点线代数（叉积/点积），<150 行；Vitest 覆盖"麻叶三族 60° 求交""边界裁剪""非整数交点精度 1e-9"等用例。
> 若将来需要"斜接/燕尾端"等工艺表达，在 segment 上附加 `end: {type:'miter', angle:...}` 元数据，不影响坐标派生。

## 5. 渲染与交互架构（SVG）

### 5.1 视图管线
```vue
<!-- KumikoCanvas.vue -->
<svg :viewBox="viewBox" @mousedown="onDown" @mousemove="onMove" @mouseup="onUp">
  <GridLayer     />        <!-- mm 刻度网格（物理坐标，随 viewBox 缩放） -->
  <PatternLayer  />        <!-- v-for="s in segments" → <line>（含选中高亮、尺寸标注） -->
  <InteractionLayer />     <!-- 框选矩形、吸附指示、画族预览 -->
</svg>
```
- `viewBox = `${pan.x} ${pan.y} ${viewportW/zoom} ${viewportH/zoom}``（视口尺寸需换算）
- 滚轮缩放以光标为锚点、空格/中键平移、双击适配全图。
- **精度策略**：SVG 以 mm 逻辑坐标绘制，任意缩放不模糊；光标位置 → 世界坐标 = `(screen - pan)/zoom`。

### 5.2 交互
- **点选**：`<line>` 原生 click（每段可点）；Shift 多选；点空白清空。线段细时加命中容差（透明的加宽 hit-area 平行于线段绘制）。
- **框选**：交互层拖出 SVG rect，与线段做包围盒相交测试。
- **画线族**（pattern 工具）：① 点按设定 ref 起点 → 拖拽决定角度（自动吸附到 angleStep 步进）→ 松开弹属性面板填 spacing/count → 生成线族；或 ② 面板直接输入参数放置。
- **吸附**：绘制 ref 点/拖拽端点时吸附到 grid（1mm 或自定义）；角度吸附 `snap.angleStep`。
- **撤销/重做**：所有 mutation 走 history 包装（见 §8.2）。

### 5.3 尺寸标注显示
- 不默认铺满全图（会花屏）。策略：**选中/悬停段显示长度**；侧栏"显示全部标注"开关；线族编辑时显示 `spacing` 批注。
- 文本用 SVG `<text>`，字体大小按 `物理字号/zoom` 保持屏幕恒定可读。

## 7. 开发阶段（MVP 路线图修订）

- **Phase 1（核心闭环）**：Vite + Vue3 + SVG 画布；视图缩放平移；一个平行线族可显示；`core/geometry` + `core/patterns/derive` + Vitest；选中/高亮；**撤销/重做**；属性面板改 angle/spacing/count/width 即时重排；长度标注（选中/悬停）。
- **Phase 2（编辑能力）**：多线族叠加、框选/多选、族级增删、段级宽度覆盖；**网格吸附 + 角度步进**；导出 SVG 文件。
- **Phase 3（算料）**：`core/cutlist` 1D 下料；材料规格（标准条长/kerf/端部处理）设置；CutListPanel 输出分组清单 + 总长/余料/利用率。**此阶段若排样搜索变慢再引入 Worker**。
- **Phase 4（AI 可选）**：`core/presets` 参数化纹样库（麻叶/菱形/斜格…）；接入 LLM 仅做自然语言 → 参数对象解析；渲染走本地生成器。
- **Phase 5（桌面可选）**：Tauri 打包 Web 应用。

## 8. 核心实现要点（编码指引）

### 8.1 派生缓存
`deriveSegments` 是纯函数；在组件/composable 层做缓存：`patterns 版本号或引用变化才重算`。PatternLayer 渲染只依赖派生段，避免派生段进入 Pinia 响应式（它们量大且只读）。

### 8.2 撤销/重做
```javascript
// stores/history.js
// 动作前 pushState()：快照 project 的 JSON（patterns/material）
// undo()/redo()：栈指针移动 → 整体替换 project 纯数据
```
- 快照间隔去抖（如连续拖拽调间距时以 pointerup 为界入栈）。
- 快照仅存纯数据（JSON），天然免疫"几何对象实例进响应式"陷阱；容量见 §8.6。

### 8.3 单位与渲染换算（约定）
- store 与 core 中所有数值均为 **mm**。
- `PatternLayer` 的 `stroke-width = width × zoom`（SVG 内若用 viewBox 则浏览器自动缩放 line 坐标，但 stroke-width 需显式乘 zoom —— 若把 stroke 理解成"物理木条宽"，正确语义是随 zoom 变宽）。
- 字号：`labelFontPx / zoom` 反向补偿保持可读。
- 输入框均以 mm 为单位，显示保留 1 位小数（0.1mm 精度）；间距类输入（线族 `spacing` / 单线相邻线间距）例外——按「全局间距单位」的整数倍 Nx 用下拉选择（换算：间距 mm = N × spacingUnit）。

### 8.4 命中与拾取
- 细线（<4px 屏显）点击难命中：为每段绘制一条不可见 `stroke-width=10px` 的透明 hit-path 承载 click（或统一 pointer-events 容差策略）。
- 框选矩形与 `bounds`、线段的相交判断放 core/geometry（可单测）。

### 8.5 修改路径（全部走纯数据）
```
面板输入 → store action（包 history push）→ patterns 更新
        → deriveSegments()（缓存失效重算）→ PatternLayer 自动重渲染
```
禁止在组件里直接改 Konva/SVG 节点状态——SVG 是数据的投影。

### 8.6 持久化与容量
- 仅持久化 `project`（patterns 通常 KB 级，安全）；**不持久化**派生段与 ui 态。
- localStorage 上限 ~5MB：若未来图库/多项目增多，切换 IndexedDB（写一个 `storage` 抽象，一处替换）。快照历史默认不持久化（会话内即可），或仅保留最后 N 条。

### 8.7 AI（Phase 4）架构约束
- LLM 输出必须是**参数对象**（JSON schema 校验，function-calling/JSON mode），如：
  ```json
  { "preset": "asano-ha", "widthMm": 300, "spacing": 8, "barWidth": 3 }
  ```
- 几何永远由 `core/presets` 生成器产出；LLM 不接触坐标。上下文里给模型"可用预设清单 + 参数约束"而非让它算几何。

## 9. 常见陷阱与解决方案（修订）

| 陷阱 | 解决方案 |
|------|----------|
| 把派生 segments 存进 Pinia 响应式 | 派生段只读、缓存于 composable/getter，不入 store state |
| SVG 线宽不随缩放（stroke 固定 px） | 线宽是"物理 mm"，`stroke-width = width × zoom`；字体反向补偿 |
| 全图标注铺满花屏 | 默认仅选中/悬停显示，另有全显开关 |
| 频繁拖动导致重复全量求交 | 求交是纯函数 + 版本缓存；拖拽以 pointerup 结算派生 |
| undo 粒度太粗/太细 | 以"一次完整编辑动作"为入栈粒度，连续拖拽按 pointerup |
| localStorage 顶容量 | 只持久化 project 纯数据；预留 IndexedDB 存储抽象 |
| 角度约定混乱（y 轴向下的 60° 朝向） | core/angle.js 统一定义：画布 y 向下，正角 CCW，全部走归一化 |
| 细线点击难命中 | 透明加宽 hit-path 承载事件 |
| LLM 幻觉坐标 | AI 只输出参数，几何由本地生成器产出（§8.7） |
