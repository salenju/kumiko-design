## 1. 关键决策（已与需求方确认）

| 决策点 | 结论 |
| --- | --- |
| 「末端角度」含义 | **木条在图案边缘的切口角**：图案落在面板 / 格子边界时，木条末端的斜切 / 拼接角度 |
| 「初始化框架」产物 | **用线条生成格子框架**：按行列生成 rows+1 条横线 + cols+1 条竖线（真实木条），划分出 x×y 个单元格作为图案库模块的容器 |
| 图案库形态 | **四合一**：① 新增「图案库」抽屉面板；② 保留参数弹窗；③ 从画布框选「存为图案」；④ 从面板拖拽到画布摆放 |
| 入口合并 | 原「＋ 预设纹样」**并入「▤ 图案库」并删除**（3 种预设即内置模块，参数弹窗由卡片的「参数」承担）；「▦ 初始化框架」**保持独立**（骨架 ≠ 内容），但在图案库面板顶栏提供快捷入口 |
| 非标准图案名 | 麻叶 / 井字 / 龟甲按组子惯例给出确定几何；手牵手 / 广场舞给出**候选定义**（见 §4），几何由配置驱动，可低成本替换 |
| 参考网站 | mikos.app 为纯前端 SPA，静态抓取无有效内容，**不作为几何依据**；仅作交互形态参考 |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 图案模块（PatternModule） | 图案库中的一条**参数化图案定义**（内置或用户自定义） |
| 模块实例（PatternGroup） | 图案模块在画布上的**一次使用**，展开为若干线族 / 线段 |
| 线族（family） | 现有数据模型：一组等距平行线 `{ref, angle, spacing, count, width, bounds}` |
| 单线（line） | 现有数据模型：一根独立线段 |
| 段集（segs） | **新增**数据模型：一组显式线段，用于无法用平行线族表达的图案（龟甲等） |
| 槽位（Slot） | 初始化框架生成的单元格（矩形区域） |
| 末端切口角（endCut） | 木条**端面方向**与**木条方向**的夹角，单位 °，默认 `90`（= 方切 / 垂直截断） |
| 图案分类（category） | 图案库的一级分组：基础网格 / 花叶纹样 / 几何纹样 / 连缀纹样 / 我的图案 |

## 3. 需求一：图案库

### 3.1 目标

把「一种图案」沉淀为**可参数化、可分类、可复用**的模块：用户从库里挑一种图案，设定尺寸 / 间距 / 木条宽 / 末端切口角后插入画布；插入后仍是「一个整体」，可整体再调参、可整体删除；图案部件统计按库里分类维度分别罗列。

解决的问题：不再为每种图案单独写一套硬编码交互，新增图案 = 在目录里加一条配置。

### 3.2 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | 图案库面板 | 工具栏「▤ 图案库」打开右侧抽屉；左侧分类导航，右侧缩略图卡片网格；顶部搜索框（按名称） |
| F2 | 分类分组 | 一级分类：**基础网格 / 花叶纹样 / 几何纹样 / 连缀纹样 / 我的图案**；「我的图案」为用户「存为图案」所得 |
| F3 | 缩略图 | 每个模块渲染一张按自身几何缩放的 SVG 缩略图（不依赖画布数据，离线可用） |
| F4 | 点击插入 | 点击卡片 → 直接插入画布：若已选中某个槽位则填入该槽位；否则插入到当前视图中心，按模块默认尺寸 |
| F5 | 参数弹窗 | 卡片上的「参数」按钮 → 弹窗设置尺寸 / 间距 / 木条宽 / 末端切口角，确认后插入（复用现有预设弹窗的交互形态） |
| F6 | 拖拽摆放 | 从卡片按住拖到画布，落点跟随光标预览；释放时：落在槽位上则**吸附到槽位**，否则以落点为中心自由放置。鼠标与触控均可用（基于 Pointer Events） |
| F7 | 实例再编辑 | 选中画布上的模块实例（选中其任一线族 / 线段即选中整个实例）→ 右侧属性面板可改该实例的参数（间距 / 木条宽 / 末端切口角）并整体重建几何 |
| F8 | 存为图案 | 画布框选若干图案 → 「＋ 存为图案」→ 记录名称与分类，**以选中内容的外接矩形归一化**为自定义模块，写入「我的图案」 |
| F9 | 自定义图案管理 | 自定义图案持久化在 **localStorage**（跨作品可用，独立于作品数据）；支持重命名、删除、复制 |
| F10 | 与初始化框架联动 | 启用初始化框架后：点击槽位可选中格子；选中格子后点击图案库条目 → 填入该格；模块实例记录 `cell:{row,col}`，框架行列 / 间距变化时自动重建几何 |
| F11 | 入口合并（旧「预设」下线） | 原「＋ 预设纹样」（麻叶/方格/斜格）**并入图案库**：其 3 种图案即图案库内置模块，参数弹窗由卡片的「参数」承担；工具栏图案组精简为「▤ 图案库」+「✦ AI 生成」；`core/presets/` 与 `PresetsModal.vue` 删除；`ai/parseIntent.js` 改为输出 `moduleId` 并走图案库插入（结果为整体实例），别名扩展到 6 种图案 |

### 3.4 数据模型

**模块定义（PatternModule，代码常量或自定义记录）**

```jsonc
{
  "id": "mod-asanoha",
  "name": "麻叶",
  "category": "flower",          // CATEGORIES 的 key
  "desc": "三组互成 60° 的平行线族",
  "express": "family",            // 'family' | 'segs'
  "defaults": { "size": 300, "spacing": 20, "width": 4, "endCut": 90 },
  "schema": [ /* { key, label, unit, min, max, step } …… 用于参数弹窗 */ ],
  "generate": "({ rect, params, endCut, groupId }) => Pattern[]"
}
```

**模块实例（PatternGroup，随项目持久化）**

```jsonc
{
  "id": "grp_xxx",
  "moduleId": "mod-asanoha",
  "name": "麻叶",
  "category": "flower",
  "params": { "spacing": 20, "width": 4, "endCut": 90, "size": 300 },
  "cell": { "row": 1, "col": 2 },   // 绑定初始化框架的格子；null = 自由放置
  "patternIds": ["pat_xxx-0", "pat_xxx-60", "pat_xxx-120"]
}
```

约束：
- `PatternGroup` 存入 `project.groups`，**参与撤销 / 持久化 / 导出**；
- 展开出的每个 `pattern` 附加 `groupId` / `moduleId`（持久化，便于恢复后重建关联）；
- 端面线、槽位、缩略图为**派生数据**，不入库。

**末端切口角**：存在 `PatternGroup.params.endCut`（实例级）；自由绘制的线族 / 单线无实例，等效方切（90°），可在属性面板单独设置（存 `pattern.endCut`）。

### 3.5 图案库的使用方式

1. **选图案**：工具栏「▤ 图案库」→ 左侧选分类 → 右侧看到该分类下所有图案的缩略图。
2. **直接插入**：点缩略图卡片 → 图案出现在当前视图中心（或已选中的槽位里）。
3. **带参数插入**：点卡片「参数」→ 在弹窗里设尺寸 / 间距 / 木条宽 / 末端切口角 → 「添加到画布」。
4. **拖拽摆放**：按住卡片拖到画布，松手处即为图案中心；拖到槽位上会自动吸附。
5. **再编辑**：点选画布上的图案（任一根木条）→ 右侧属性面板出现该实例的参数区，改完即时重建。
6. **保存自绘图案**：框选画布内容 → 点属性面板或图案库里的「＋ 存为图案」→ 命名并选分类 → 出现在「我的图案」。
7. **配合初始化框架**：先「▦ 初始化框架」生成 x×y 槽位 → 逐个把图案填入格子 → 改框架行列 / 间距时图案跟着格子走。

### 3.6 图案库的使用示例

**示例 A：3×4 格的麻叶屏风**

1. 初始化框架：行 3、列 4、单元格 200×200mm、间距 20mm、末端切口角 45°。
2. 图案库 → 花叶纹样 → 麻叶，参数设 间距 20mm、木条宽 4mm，交替填入 12 个格子。
3. 因末端切口角统一为 45°，相邻格子之间的木条端面方向一致，拼接处可平顺对接。
4. 打开「🔩 图案部件」→ 切到「按图案分类」视图 → 看到「花叶纹样 · 麻叶」下若干组同型部件（尺寸 / 间距缩写 / 数量）。

**示例 B：混搭井字与龟甲**

1. 图案库 → 基础网格 → 井字，拖拽到画布左上自由摆放。
2. 图案库 → 几何纹样 → 龟甲，拖到井字右侧，落点吸附到最近的空格。
3. 部件面板按分类分别罗列井字与龟甲所需的木条尺寸、间距、数量。

**示例 C：自绘图案复用**

1. 手工用「画线族」画出一种自己的图案组合，框选。
2. 点「＋ 存为图案」，命名「我的三角网格」。
3. 新建作品后打开图案库 → 「我的图案」→ 直接插入复用。

## 4. 内置图案的几何定义

统一约定：角度为 y-down 画布下的度（0° = 水平向右，90° = 竖直向下）；`rect` 为图案外接矩形；`s` 为间距（相邻平行线中心距）；`width` 为木条宽。

| 图案 | 表达 | 几何定义 |
| --- | --- | --- |
| **井字（方格）** | 线族 | 角度 `0°` 与 `90°` 两组等距平行线，间距 `s`，覆盖 `rect` |
| **斜格** | 线族 | 角度 `45°` 与 `135°` 两组等距平行线，间距 `s`，覆盖 `rect` |
| **麻叶** | 线族 | 角度 `0°`、`60°`、`120°` 三组等距平行线，间距均为 `s`，覆盖 `rect`（正三角形网格 → 六角星连缀，即麻叶纹） |
| **龟甲** | 段集 | 正六边形（平顶）蜂窝网格：六边形边长 `a = s / √3`（`s` 为对边距）；中心点阵 `x = i·1.5a`、`y = j·s + (i mod 2)·s/2`；顶点角 `0°,60°,…,300°`，半径 `a`；生成全部六边形边后**去重共享边**并**共线相邻段合并**，按 `rect` 裁剪 |
| **手牵手**（候选） | 线族 | 竖直组 `90°`（间距 `2s`）+ 两组斜线 `60°`、`120°`（间距 `s`）。竖线之间形成 X，X 的上下顶点落在竖线上并与相邻单元相接 —— 视觉上即「一排小人手拉手」 |
| **广场舞**（候选） | 线族 | 方格 `0°`、`90°`（间距 `s`）+ 斜格 `45°`、`135°`（间距 `s/√2`，与格心对齐）。每格内形成菱形、格点处形成八角星 —— 视觉上如「方阵中起舞」 |

> **手牵手 / 广场舞为候选定义**：这两个名称非标准组子术语，需求方将提供参考图后按图校正。由于全部由配置（角度组 + 间距关系）驱动，校正成本 = 改 `catalog.js` 中一条定义，不涉及引擎改动。

## 5. 需求二：初始化框架

### 5.1 目标

按 x 行 / y 列 / 间距，**用线条**生成一个格子框架（**不是虚线块状槽位**）：

```
横线（angle 0°）  rows + 1 条，中心距 pitchY
竖线（angle 90°） cols + 1 条，中心距 pitchX
```

这些线是**真实木条**：它们相互求交后被切成单元格边界段，即形成所见网格（如参考图中的方格框架）。框架把面板划分成 x×y 个单元格，用于「点格子 → 从图案库填入图案」。

### 5.2 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| L1 | 参数弹窗 | 工具栏「▦ 初始化框架」→ 输入：**行数 x、列数 y、横向间距、纵向间距、起点坐标、框架木条宽、末端切口角、单元格高亮开关** |
| L2 | 生成线条 | 由 `core/library/frame.js` 生成横线族 + 竖线族（`kind:'family'`），带 `frame:true` 标记 |
| L3 | 单元格派生 | `cellRect = { origin.x + col·pitchX, origin.y + row·pitchY, pitchX, pitchY }`（派生，不入库） |
| L4 | 单元格选中 | 单击画布上的单元格 → 选中（蓝色高亮 + 行列号）；再次点击空白取消 |
| L5 | 填充图案 | 选中单元格后：点击图案库条目 / 拖拽到该格 → 实例绑定 `cell:{row,col}`，几何按单元格矩形生成 |
| L6 | 参数调整 | 改行列 / 间距 / 起点 → **线条整体重建**，且绑定实例自动跟随重排（一次撤销粒度） |
| L7 | 高亮开关 | 单元格高亮可显示 / 隐藏（`ui.slotVisible`），不影响线条与数据 |
| L8 | 清除框架 | 「清除框架（保留图案）」= 移除线条与绑定；「清除框架与图案」= 连实例图案一起删（二次确认） |
| L9 | 线条保护 | 框架线不参与单独选择编辑与删除（由框架参数统一管理），避免与参数脱节 |

### 5.3 数据模型

```jsonc
// project.layout（随项目持久化）
{
  "enabled": false,
  "rows": 3,                        // 行数 x（单元格行数）
  "cols": 4,                        // 列数 y（单元格列数）
  "pitchX": 200,                    // 横向间距 = 相邻竖线中心距 = 单元格宽
  "pitchY": 200,                    // 纵向间距 = 相邻横线中心距 = 单元格高
  "origin": { "x": 0, "y": 0 },     // 左上角交点（第一条横线 × 第一条竖线的交点）
  "width": 3,                       // 框架木条宽
  "endCut": 90                      // 框架线条末端切口角
}
```

框架线条（`src/core/library/frame.js`）：

```jsonc
// 横线
{ "id": "frame-h", "kind": "family", "ref": {"x": x0, "y": y0}, "angle": 0,
  "spacing": pitchY, "count": rows + 1, "width": width, "bounds": {...},
  "frame": true, "moduleId": "mod-frame", "endCut": 90 }
// 竖线（ref 取右上角，因 90° 的法向为 (-1,0)，线集仍覆盖 x0 … x0+cols·pitchX）
{ "id": "frame-v", "kind": "family", "ref": {"x": x0 + cols·pitchX, "y": y0}, "angle": 90,
  "spacing": pitchX, "count": cols + 1, "width": width, "bounds": {...},
  "frame": true, "moduleId": "mod-frame", "endCut": 90 }
```

单元格推导（`src/core/library/layout.js`）：

```
cellRect(layout, row, col) = {
  x: origin.x + col · pitchX,
  y: origin.y + row · pitchY,
  w: pitchX,
  h: pitchY
}
layoutBounds(layout) = { x: origin.x, y: origin.y, w: cols·pitchX, h: rows·pitchY }
```

约束：
- 框架线条**是** `project.patterns` 的成员（参与求交派生 / 算料 / 部件统计 / 导出），由 `project.syncFrame()` 在 layout 变化时整体替换；
- 单元格为**派生 getter**，不入库（改参数即自动重排）；
- 实例的 `cell` 为唯一绑定关系；`cell` 越界（行列被调小）时保留数据并回退为实例当前实际位置，可用「按框架重排」或直接拖回格子。

## 6. 末端切口角（endCut）

### 6.1 定义

**末端切口角 `endCut` = 木条端面方向与木条方向的夹角**，单位 °：

- `endCut = 90`：端面垂直于木条 → **方切**（默认，等同于普通截断）；
- `endCut = 45`：端面与木条成 45° → **45° 斜切**（拼接边框的常见做法）；
- 有效范围建议 `10 ~ 170`（避开退化为与木条平行的端面）。

端面线方向（世界坐标） = 木条方向角 `θ + endCut`。

### 6.2 作用范围

| 位置 | 说明 |
| --- | --- |
| 图案模块实例 | `group.params.endCut`，作用于该实例展开的全部木条末端 |
| 初始化框架 | `layout.endCut` 作为新建实例的默认值 |
| 自由绘制的线族 / 单线 | `pattern.endCut`（可选），默认方切 |

「末端」的判定：段端点落在其所属图案 `bounds` 的边界上（容差 0.05mm）。落在图案内部的交点为**插口**，不是末端，不绘制端面线。

### 6.3 渲染与交互

- **端面线**：仅当 `endCut ≠ 90` 时绘制，以端点为中点、长度 `max(width, 6/zoom)`、方向 `θ + endCut`，颜色与木条一致但略深，线尾为 `butt`。
- **hover 展示角度**：鼠标 / 触控悬停某段木条时，在其末端点外侧显示 `90°` / `45°` 等角度标注（屏幕恒定字号，白描边，不遮挡图形）。
- **属性面板**：选中实例后提供「末端切口角」数字输入（步进 5°），修改后即时重建端面线；自由线族亦有同名字段。
- **端面线不参与**：派生段、算料长度、部件统计的插口计算（斜切只改变端部形状，不改变木条中心线长度）。

### 6.4 验收标准

- [ ] 实例末端切口角默认 90°（方切），不绘制额外端面线。
- [ ] 改为 45° 后，图案外边界每一根木条的末端都出现 45° 斜切端面线。
- [ ] 悬停任一木条，其边界端出现角度标注；内部插口端不显示。
- [ ] 改末端切口角不影响木条长度、不算作插口、不改变算料结果。
- [ ] 端面线在缩放时粗细 / 长度视觉稳定。

## 11. 已按默认处理（如有异议请指出）

| 项 | 默认取值 |
| --- | --- |
| 「末端角度」定义 | 端面方向与木条方向的夹角，默认 90°（方切） |
| 端面线绘制 | `endCut = 90°` 时不绘制（避免噪点）；`≠90°` 时绘制 |
| 端面线是否影响算料 | 不影响（只改端部形状，不改中心线长度与插口） |
| 手牵手 / 广场舞几何 | 采用 §4 候选定义，待参考图校正 |
| 龟甲表达 | 段集（正六边形网格），共享边去重 + 共线合并 |
| 自定义图案存储 | localStorage 单 key（`kumiko:pattern-library:v1`），跨作品可用 |
| 「存为图案」的归一化方式 | 以选区外接矩形归一化到单位正方形，插入时按目标 rect 缩放 |
| 初始化框架的产物形态 | **线条**（横线 rows+1 条 / 竖线 cols+1 条，真实木条），不是虚线块状槽位 |
| 框架线条的归属 | 存入 `project.patterns`（`frame:true` / `moduleId:'mod-frame'`），参与求交/算料/部件/导出；由 `syncFrame()` 随 layout 整体重建 |
| 框架线条是否可单独编辑删除 | 否（由框架参数统一管理），复制时跳过 |
| 单元格数据形态 | 由 `layout` 参数派生，不入库 |
| 单元格高亮层职责 | 只标选中格与已填充格（轻量提示），不绘制全部格的虚线框 |
| 行数 / 列数的语义 | 单元格行数 / 列数（线条数 = 行数+1 / 列数+1） |
| 间距的语义 | 相邻平行线中心距（= 单元格宽 / 高） |
| 拖拽技术 | Pointer Events（兼容鼠标与触控），非 HTML5 DnD |
| 自由绘制的末端角 | 默认 90°，可在属性面板单独设置（存 `pattern.endCut`） |

## 13. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 手牵手 / 广场舞定义与预期不符 | 图案外观不对 | 几何全配置化，改 `catalog.js` 一条定义即可校正 |
| 龟甲段集数量大（大尺寸 + 小间距） | 渲染 / 统计变慢 | 共线合并减少段数；`segs` 不参与跨图案求交，避免 O(n²) 派生 |
| 槽位绑定实例在框架变更后错位 | 几何不跟随 | 统一走 `rebuildGroups`，一次撤销粒度；越界标记 dangling 并提示 |
| 自定义模块存储被清理 / 换设备丢失 | 图案丢失 | 面板内提示存储位置；后续可随项目文件携带（见开放问题 4） |
| 端面线在极端缩放下过短 / 过长 | 视觉噪声 | 长度取 `max(width, 6/zoom)`，屏幕视觉恒定 |
