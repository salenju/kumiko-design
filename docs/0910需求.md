## 0. 原始诉求（原文保留）

> ### 1. 支持暂存在工作区，支持从工作区恢复，方便随时打开编辑
> ### 2. 日常是在 pad 上使用，可以做成 pwa 这类 app 提供安装么

## 1. 结论速览（已确认决策）

| 决策点 | 结论 |
| --- | --- |
| 需求1「工作区」形态 | **应用内作品库**（作品列表 + 暂存/恢复/管理），不依赖 File System Access API |
| 作品文件粒度 | **一个文件 = 一个作品**（每个作品导出为独立 `.kumiko.json`） |
| 落盘方式 | 一键导出到系统「下载」目录；用系统文件选择器（`<input type="file">`）导入 |
| 数据迁移 | 首次启动把现有 `localStorage` 单项目自动迁入工作区，不丢数据 |
| 持久化存储 | 申请 `navigator.storage.persist()`，降低被系统清理风险 |
| 容量与备份 | 显示已用容量 / 配额，提供「一键导出全部作品」备份 |
| 删除策略 | 软删除进「回收站」，删除/彻底删除/清空均需二次确认 |
| 需求2 目标平台 | **Android 平板 Chrome**（完整 PWA 支持） |
| 离线能力 | **完全离线可用**（Service Worker 预缓存全部静态资源） |
| 部署 | **GitHub Pages**（HTTPS、子路径部署，需 public 仓库） |

### 关键技术约束（务必知悉）

`File System Access API`（`showDirectoryPicker` / `showSaveFilePicker`）**在 Android Chrome 上不被支持**（caniuse 数据：Chrome for Android 至今标记为 ❌，桌面 Chrome 105+ 才支持；MDN 亦说明移动端 Chrome 长期未支持 Picker 系列）。

因此原始设想「把作品存到 pad 某个目录并从目录打开」在纯 PWA 下无法实现，本方案改为：

- **应用内工作区**（真正的暂存/恢复载体，持久化在浏览器存储中）
- **导出 = 下载到系统目录**（`.kumiko.json` 落到「下载」，用户自行归档）
- **导入 = 系统文件选择器**（可从任意目录/云盘选文件）

> 若将来必须直接读写 pad 任意目录，唯一路径是上原生壳（Capacitor / Tauri Mobile）——**不在本次范围**。

## 2. 需求一：应用内工作区（作品库）

### 2.1 目标

让「作品」成为一等公民：多份作品可长期暂存在应用内，随时切换打开继续编辑；并且随时能导出成真实文件、从文件恢复。

### 2.2 用户故事

- 作为使用者，我在 pad 上画到一半关掉浏览器，下次打开能**原样继续**。
- 作为使用者，我可以同时保存多个作品（如「麻叶纹 300」「方格 600」），在列表里**点一下就能切换**。
- 作为使用者，我担心浏览器清理数据，所以能**一键导出全部作品**做备份，也能把某一份导出成文件发给别人。
- 作为使用者，我误删了作品，能去**回收站**找回来。

### 2.3 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | 工作区列表 | 卡片/列表展示每个作品的：名称、更新时间、缩略图（失败则回退为「N 图案 · M 段」）、占用大小；按更新时间倒序 |
| F2 | 打开/切换 | 点作品即载入当前画布（替换当前项目），并清空撤销历史、选中态、视图复位 |
| F3 | 新建 | 新建空白作品并自动命名「未命名作品 N」 |
| F4 | 自动暂存 | 编辑后防抖（约 400ms）自动写回**当前作品**，替代当前的单 key 自动保存 |
| F5 | 重命名 | 就地重命名（长度上限 60，去首尾空白，同名校验提示允许重名） |
| F6 | 复制 | 复制为新作品「原名 副本」 |
| F7 | 删除 | 软删除进回收站；回收站支持「恢复 / 彻底删除 / 清空回收站」；删除、彻底删除、清空**均需二次确认** |
| F8 | 导入 | 系统文件选择器选 `.kumiko.json`（支持多选），导入为**新作品**（不覆盖当前作品），同名自动加序号 |
| F9 | 导出单个 | 把某作品导出为 `<名称>.kumiko.json` 下载 |
| F10 | 一键备份 | 导出全部作品为 `<日期>.zip`，内含每作品一个 `.kumiko.json` + `manifest.json`（清单：名称/时间/版本） |
| F11 | 容量展示 | 展示已用容量 / 配额（`navigator.storage.estimate()`）；达 80% 时提示备份 |
| F12 | 持久化存储申请 | 首次成功保存后申请 `navigator.storage.persist()`；未授予时明确提示「数据可能被系统清理，建议备份」 |
| F13 | 数据迁移 | 首次启动时把现有 `localStorage`（`kumiko:project:v2`）中的项目迁入为第一个作品；迁移后清理旧 key |
| F14 | 兼容旧交互 | 保留现有「⇩ 导出文件 / ⇧ 导入文件」入口语义，指向上述导入导出；`⌘S` 由「写 localStorage」改为「立即写回当前作品」 |

### 2.4 数据模型

**作品记录（object store `works`，keyPath `id`）**

```jsonc
{
  "id": "w_xxx",                 // uid('w')
  "name": "麻叶纹 300",
  "createdAt": 1757462400000,    // ms
  "updatedAt": 1757462400000,    // ms
  "deletedAt": null,             // null=正常；时间戳=回收站
  "size": 12345,                 // 序列化后字节数
  "thumbnail": null,             // 'data:image/svg+xml;base64,...' 或 null
  "data": {                      // 与现有 project 纯数据完全一致
    "version": 5,
    "patterns": [],
    "material": { "stockLength": 1200, "kerf": 1.5, "endAllowance": 2 },
    "spacingUnit": 10,
    "lineColors": { "fallback": "…", "angles": [] }
  }
}
```

**元数据（object store `meta`，keyPath `key`）**

| key | value | 用途 |
| --- | --- | --- |
| `schemaVersion` | `1` | 迁移判定 |
| `currentWorkId` | `w_xxx` | 上次打开的作品，启动时恢复 |
| `lastBackupAt` | 时间戳 | 备份提醒（可选） |

**约束**：`works.data` 只存纯数据，不含派生 `segments` 与 ui 态（沿用 V2 §8.6 原则）。缩略图为派生数据，落库前生成、可随时重建。

### 2.5 存储方案

- **引擎**：IndexedDB（DB 名 `kumiko-workspace`，版本 1），替代当前 `localStorage` 单 key。
  - 理由：容量远大于 localStorage（~5MB）、原生支持按 key 读写单个作品、避免大 JSON 全量重写；与 V2 §8.6 预留的「切 IndexedDB」方向一致。
- **抽象层**：新增 `storage` 适配（沿用 `persist.js` 的单点替换思路），IndexedDB 不可用（隐私模式等）时降级回 `localStorage`，并在 UI 提示「当前为兼容模式，容量有限」。
- **自动保存**：仅写回当前作品一条记录（不是整库），防抖 400ms；同时更新 `updatedAt` / `size`。
- **缩略图**：保存时惰性生成（复用 `buildSvgString` 思路，宽度约 200px 的 SVG → dataURL），生成失败置 `null`，不阻塞保存。
- **不删除旧存档**：迁移完成后删除 `kumiko:project:v2`；若迁移前用户清空过数据则直接新建空白作品。

### 2.6 UI 落点

- 工具栏「文件」组新增 **「🗂 工作区」** 按钮（打开工作区抽屉/弹窗）；原有的「新建 / 保存 / 导出文件 / 导入文件」保留在工具栏，语义对齐 F13/F14。
- **工作区面板**（抽屉，适配 pad 宽屏）：
  - 顶部：搜索框（按名称）、「＋ 新建」、「⇧ 导入」、「⇩ 备份全部」、容量条
  - 列表：缩略图 + 名称 + 时间 + 大小 + 操作（打开 / 重命名 / 复制 / 导出 / 删除）
  - 底部：「♻ 回收站」入口（切换视图，显示已删除作品与恢复/彻底删除/清空）
- 当前作品名显示在工具栏状态区（如 `麻叶纹 300 · 3 图案 · 12 段`），支持点击直接打开工作区。

### 2.7 验收标准

- [ ] 关掉浏览器/杀进程后重开，画布与上次编辑**完全一致**（含材料参数、间距单位、线条配色）。
- [ ] 可同时保存 ≥10 个作品，列表可切换打开，切换后数据各自独立、互不串改。
- [ ] 编辑 A 作品后再切到 B，A 的改动已自动保存（无需手动点保存）。
- [ ] 旧版 localStorage 数据首次启动后被迁入为第一个作品，内容无损；旧 key 已清理。
- [ ] 「导出」得到 `<名称>.kumiko.json`，可被「导入」还原出相同内容。
- [ ] 「备份全部」得到 zip，解压后每作品一个 `.kumiko.json`，逐个可导入。
- [ ] 删除的作品进入回收站，可恢复；「彻底删除」「清空回收站」均有二次确认。
- [ ] 容量与配额正确展示；申请持久化存储的结果有明确反馈。
- [ ] pad 上（Android Chrome）整套流程可触控完成，无依赖 hover 的操作。

### 2.8 边界与非目标

- **不做**：直接读写 pad 任意目录（Android Chrome 不支持）、云端账号同步、多设备实时协同。
- **不做**：作品文件夹/分组/标签（本期扁平列表；列为后续扩展）。
- **不做**：版本历史/自动快照（仍只保留会话内撤销栈，不持久化）。
- **注意**：卸载 PWA 或清除站点数据会**连带删除**工作区内容，因此 F10 备份与 F12 持久化申请是必要配套。

## 3. 需求二：PWA（可安装 + 完全离线）

### 3.1 目标

在 Android 平板 Chrome 上把本应用「安装到主屏幕」，全屏运行、断网可用，体验接近原生 App。

### 3.2 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| P1 | 可安装 | 合法 Web App Manifest（名称、图标 192/512/maskable、`display: standalone`、`start_url`/`scope` 适配子路径） |
| P2 | 安装引导 | 监听 `beforeinstallprompt`，在工具栏/设置中提供「安装到主屏」按钮；已安装（`display-mode: standalone`）时隐藏；`appinstalled` 后提示 |
| P3 | 完全离线 | Service Worker 预缓存**全部**静态资源（JS/CSS/HTML/图标/字体），断网冷启动可用 |
| P4 | 更新提示 | 检测到新版本时提示「有新版本，点击刷新」，避免编辑中被强制刷新（不静默刷新） |
| P5 | 全屏与安全区 | standalone 下适配刘海/圆角（`viewport-fit=cover` + safe-area，已具备）；`theme_color` 与应用主色一致 |
| P6 | 持久化存储 | 与 F12 联动，安装态下优先申请持久化存储 |
| P7 | 启动画面 | 由 manifest 图标 + `background_color` 生成，无白屏闪烁 |

### 3.3 技术方案

- 依赖：`vite-plugin-pwa`（最新 `1.3.0`，`peerDependencies.vite` 已声明 `^3.1 ~ ^8.0`，**兼容本项目 Vite 8**）。
- 构建配置（`vite.config.js`）要点：
  - `base`：从环境变量读取（如 `BASE_PATH`），本地默认 `/`，GitHub Pages 为 `/<repo>/`。
  - `VitePWA({ registerType: 'prompt', manifest, workbox })`：
    - `manifest`：`name/short_name/description/lang: 'zh-CN'/theme_color/background_color/display: 'standalone'/orientation: 'any'/start_url: '.'/scope: '.'/icons`
    - `workbox`：`globPatterns: ['**/*.{js,css,html,svg,png,ico,woff2}']`、`navigateFallback: 'index.html'`、`cleanupOutdatedCaches: true`、按需调大 `maximumFileSizeToCacheInBytes`
  - 全量引入 Naive UI 会让包体偏大，**离线要求下必须全量预缓存**，首次访问后即可离线；体积优化（按需引入）列为后续项。
- 注册与更新：`src/main.js` 使用 `virtual:pwa-register`，`onNeedRefresh` 时提示、`onOfflineReady` 时提示「已可离线使用」。
- 图标产出：新建 `public/`（`favicon.ico`、`pwa-192.png`、`pwa-512.png`、`pwa-maskable-512.png`、`apple-touch-icon.png`），用现有品牌色 `#1f4e9c` + 三角纹样图形；可用 `@vite-pwa/assets-generator` 从一张 512 源图批量生成。
- `index.html`：补 `theme-color` meta、`apple-mobile-web-app-*` meta（manifest 由插件注入）。

### 3.4 GitHub Pages 部署

- 新增 `.github/workflows/deploy.yml`：`pnpm install` → `pnpm build`（带 `BASE_PATH=/${{ github.event.repository.name }}/`）→ `actions/upload-pages-artifact` → `actions/deploy-pages`。
- 仓库 Settings → Pages → Source 选 **GitHub Actions**。
- 前提与注意事项：
  - 免费版 Pages 需 **public 仓库**（已确认接受）。
  - 子路径部署：`base` / `start_url` / `scope` 必须一致，否则 SW 注册与资源加载会 404。
  - 本项目**无路由**（单 `index.html`），无需 SPA 404 回退文件，`navigateFallback` 已足够。
  - 首次部署后需用 **HTTPS 地址**在 Android Chrome 打开才能安装。

### 3.5 验收标准

- [ ] Chrome 地址栏/菜单出现「安装应用 / 添加到主屏幕」，安装后桌面有图标、独立窗口打开。
- [ ] 安装后**开飞行模式**冷启动，应用完整可用（可新建、编辑、导出，导出走本地 Blob 不依赖网络）。
- [ ] 断网状态下重新打开仍能恢复上次作品（IndexedDB 离线）。
- [ ] 发布新版本后，旧版本提示「有新版本」，点击后刷新到新版且**数据不丢**。
- [ ] standalone 下无地址栏、无白边，横竖屏切换布局正常，安全区不被遮挡。
- [ ] `navigator.storage.persist()` 结果为已授权或给出明确提示。

### 3.6 边界与风险

- iOS Safari 仍是弱支持（无安装横幅、无 File System Access、部分版本离线受限）——**本期目标是 Android Chrome**，iOS 仅保证「能打开使用」。
- GitHub Pages 为公开站点：**作品数据只在本地浏览器**，不会被上传；但请勿把敏感内容写进作品名（名称仅存在于本地，不会出现在 URL 中）。
- 卸载 PWA = 清除该站点数据 → 工作区内容一并消失（依赖 F10 备份兜底）。
- 全量预缓存导致首次加载体积较大（Naive UI 全量引入所致），离线优先的前提下接受；后续可按需引入优化。

## 4. 触控（pad）现状评估

**已具备**（核对 `src/components/canvas/KumikoCanvas.vue`）：

- 全部交互基于 `Pointer Events`，容器设 `touch-action: none`，不会触发浏览器滚动/缩放。
- 已实现**双指 pinch 缩放 / 平移**（`activePointers` + `multiGesture`）。
- 触摸拖拽有独立阈值（`TOUCH_DRAG_THRESHOLD_PX`），触摸下不触发 hover 命中。

**本次需补的触控适配**（列入工作区改造一并处理）：

- 触摸下无 hover → 尺寸悬停提示不可用，需保证「尺 标注」开关易触达（pad 上默认开启或加大按钮）。
- 工具栏/面板控件触控目标宜 ≥ 44px；工具栏在平板上换行后的分组层级需检查。
- 工作区列表项与操作按钮需按触控尺寸设计（避免密集小按钮）。

> 触控细节优化不改变本次两项需求的核心范围，作为 pad 使用体验的必要配套。

| 空作品默认名 | 未命名作品 N |
| 缩略图 | 本期做（失败回退为统计信息） |
| 导入同名作品 | 自动加序号，不覆盖已有作品 |
| 工作区入口位置 | 工具栏「文件」组 + 状态区作品名 |
| 数据存储引擎 | IndexedDB（不可用时降级 localStorage） |

## 8. 开放问题

1. 你希望**启动时**默认打开「上次编辑的作品」，还是每次都先展示工作区列表？（当前按「默认打开上次作品」设计，可一键进工作区）
2. 工作区是否需要**搜索/排序**（按名称/时间）？当前设计含名称搜索 + 时间倒序。
3. 是否需要**锁定横屏**？（制图通常横屏更合适）
4. GitHub 仓库名是什么？（决定 Pages 的 `base` 子路径；未定可先用环境变量占位）

## 9. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Android Chrome 不支持 File System Access API | 无法直接读写 pad 目录 | 已改用应用内工作区 + 导入导出（本方案） |
| 浏览器清理站点数据 / 卸载 PWA | 作品丢失 | 申请持久化存储 + 容量提醒 + 一键备份 |
| IndexedDB 不可用（隐私模式） | 无法保存 | 降级 localStorage 并明确提示 |
| 全量预缓存体积大 | 首次加载慢 | 接受（离线优先）；后续按需引入优化 |
| GitHub Pages 子路径配置错误 | 白屏 / SW 注册失败 | `base`/`start_url`/`scope` 统一由环境变量生成，部署后真机验证 |
| 触摸无 hover | 尺寸提示不可用 | 用「尺 标注」开关兜底，pad 上默认开启 |
